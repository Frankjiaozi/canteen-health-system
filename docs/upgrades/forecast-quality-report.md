# 消耗量预测质量报告

生成时间：2026-10-19。数据来源：本机开发库 `canteen` 的演示种子，
不是真实学校台账；结论只说明算法在这份演示数据上的表现。

复现命令：

```powershell
cd apps/api
node ../../scripts/py.mjs tools/forecast_quality_report.py --days 56 --meal-type LUNCH
```

## 1. 比较对象

| 对象 | 定义 |
| --- | --- |
| 当前算法 | 最近 6 个同星期几的历史中位数/平均 × 节假日与调休修正 |
| 基线算法 | 同一历史切分、同一回退规则，但不应用节假日/调休修正 |

两者使用完全相同的日期、餐次、菜品历史、样本窗口和回退规则，只改变日历修正，
避免用不同数据切分得出“改进”的假结论。

## 2. 数据范围

```text
餐次：LUNCH
回测区间：2026-08-25 至 2026-10-19
日历天数：56
有可算样本的天数：51
当前算法样本对：222
基线算法样本对：222
```

前 5 天没有足够的同星期历史，按现有规则不产生预测；不是模型挑着算。

## 3. 结果

| 指标 | 当前算法 | 基线算法 |
| --- | ---: | ---: |
| 样本加权 MAPE | **14.43%** | **43.10%** |
| 达标线 | 20% | 20% |
| 是否通过 | **通过** | 不通过 |
| 样本对 | 222 | 222 |

按天看：

```text
可算天数：51
日 MAPE 中位数：11.01%
日 MAPE 最小：0.84%
日 MAPE 最大：158.65%
```

最大单日误差明显偏高，说明演示数据中存在小份数/低基数日期，不能只看总 MAPE
就宣称每天都很准。当前总 MAPE 是 222 个“日期 × 菜品”样本的汇总值，不是
每日 MAPE 的简单平均。

## 4. 零实际与少样本

- 实际份数为 0 的样本不进入 MAPE 分母，避免除零；如果没有任何正实际样本，
  `mape` 返回 `null`，不写成 0%。
- 同星期样本少于 3 个时，按既有规则退化为“全期平均 × 星期几规律”，并在结果
  `basis` / `basis_label` 中说明。
- 没有任何可用历史时返回空预测，不伪造一个数字。
- 当前报告只覆盖午餐；早餐和晚餐必须分别运行，不能把午餐准确率推广到三餐。

## 5. 解释边界

- 这是演示数据上的回测，不是真实食堂经营效果。
- 回测使用目标日之前的记录，不包含当天和未来数据。
- 节假日系数和小样本回退是经验假设；本报告没有证明这些假设适用于所有学校。
- MAPE 是整体误差指标，不能替代具体日期的采购复核；高波动菜品仍需看样本和区间。
- 本报告生成后计算版本升级为 `menu-plan-20261019.1`；版本升级针对默认人数/
  缩放语义，预测算法本身未改。旧版本的准确率不能自动证明新版本所有场景同样准确，
  发布前应重新运行本脚本。

## 6. 结论

在这份固定演示数据上，当前“同星期历史 × 日历修正”比不应用日历修正的基线
明显更准，整体 MAPE 从 **43.10%** 降到 **14.43%**，低于 20% 的验收线。

但结论仅限于该数据切分和午餐；报告保留高误差日期与样本边界，不把这次结果
包装成真实生产承诺。
