# 知味 Agent 升级工作记录

本次由 Ethan 授权自主推进约两小时。沿用 React / FastAPI / PostgreSQL 单仓工程；前端与 Agent 由 Ethan 负责，业务 API 与数据由搭档负责。DeepSeek 是搭档的编码助手，不代表产品选定了模型供应商。

## 本次交付

1. 新增独立 `apps/agent`：通过 HTTP 调用业务 API，独立保存对话与方案，不导入业务服务、不连接业务数据库。
2. 菜单安排、人数与预算修改、排除菜品、多版本对比、明确确认发布、采购导出；复用已有预测与求解器。
3. 近期运营核查：只使用实际接口返回的记录与异常，不推断未经证实的原因。
4. 未配置模型时使用明确标注的规则模式；配置兼容 Chat Completions 的服务后使用受约束的工具调用，发布始终由独立按钮确认。
5. 前端采用知味已有水墨身份，工作区使用墨绿 #244e43、浅绿 #edf3ee、纸白 #fbfcf9、墨色 #20332d、朱红 #a34432；清晰的任务栏、对话过程、菜单/采购结果，兼容手机。
6. 两份可独立执行的分工文档与一份共同接口契约；启动、部署与验收说明。

## 边界

- 不重置、不扩充现有业务库；集成测试使用独立测试库。
- 不读取或复用其他项目的模型密钥。不配置任何真实供应商账号。
- 不替代人工采购，不自动审批；没有模型、历史不足、求解无解时如实说明。
- 保留当前未提交的进场动画与路由改动。不自动拉取、提交或推送。

## 顺序与验收

- 先补菜单参数、不可变快照与发布接口，再实现独立 Agent、界面、对比/导出、双人文档。
- 测试覆盖登录态转发、会话归属、工具输入校验、模型失败、版本冲突、重复确认、已有采集保护；所有数字来自业务返回。
- 使用隔离 PostgreSQL 执行后端集成测试；前端测试、类型检查、构建；真实浏览器走完整流程并保存截图。
- 如未配置模型，仅声明已验证规则模式与模拟模型工具协议，不声称已验证外部模型推理。
