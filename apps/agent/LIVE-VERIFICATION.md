## 联调发现与修复

1. **模型改写数值口径。** 首轮真实回答把 `gaps` 中的整餐人均供给称作“单份口径”，并自行给出预算占比和四舍五入后的数值。新增 `answers.py`，在生成方案或读取当前方案后，使用已保存的业务字段组织事实回答；不重新计算成本、营养或占比。修复后通过真实模型解释及新方案生成验证。初始三版的旧回答保留供复盘，不改写历史记录。
2. **只读请求误判为取消。** “检查数据，列出缺项，不要生成菜单”被原取消规则直接终止。修正取消与排除菜品解析，并在生成工具入口增加明确禁止生成的校验。规则模式、模拟模型回归和真实模型早餐缺项检查均通过。

## 重现方式

服务需按上述隔离配置运行。脚本固定使用本机 8002 业务 API 和 8001 Agent，并检查 Agent 的独立演示标记；使用公开的演示账号，不重置账号。不得通过修改端口或数据标记把它指向正式数据。

在仓库根目录首次执行：

```powershell
node scripts/py.mjs apps/agent/scripts/verify_live.py --run --stage dialogue
node scripts/py.mjs apps/agent/scripts/verify_live.py --run --resume --stage safety
node scripts/py.mjs apps/agent/scripts/verify_live.py --run --resume --stage publication --publish-demo
node scripts/py.mjs apps/agent/scripts/verify_live.py --run --resume --stage extended
node scripts/py.mjs apps/agent/scripts/verify_live.py --run --resume --stage read-tools
```

真实模型可能计费，默认不会自动运行。已有输出目录应使用 `--resume`，或通过 `--output` 指定新目录；不会直接覆盖已有验收成果。扩展检查复用已完成项目，避免重复调用模型。发布验收仅选择原本无正式菜单、无采集的日期，并在结束或异常时撤回本轮临时发布；建议及审计记录保留。

本机原始证据保存在忽略提交的 `output/agent-live-check-20261019/`：`live-state.json`、`read-tools.json`、指定版本 CSV/HTML 及独立 SQLite。输出不保存 Cookie、模型密钥或隐藏思考内容。
